\subsection*{1.2 Given-When-Then Acceptance Criteria}
\begin{itemize}[leftmargin=1.5em, itemsep=3pt, topsep=3pt]
    \small
    \item \textbf{AC 1.1 (Database Seeding Counts):} \textit{Given} an empty SQLite database, \textit{When} \texttt{seed\_database()} or \texttt{POST /api/v1/admin/seed} executes, \textit{Then} 2 campuses, 5 buildings, 12 rooms, 20 users, 40 courses, 14 time slots, 6 semesters, 504 preferences, and 240 schedule records are inserted with zero foreign-key violations.
    \item \textbf{AC 1.2 (Seeder Idempotency):} \textit{Given} a seeded database, \textit{When} \texttt{seed\_database()} is called a second time without \texttt{force\_reset}, \textit{Then} no duplicate rows are created and all entity counts remain identical.
    \item \textbf{AC 2.1 (Valid CP-SAT Solve \& Persistence):} \textit{Given} seeded UMKC data for Semester 1, \textit{When} \texttt{POST /api/v1/solver/run} is called with \texttt{\{"semester\_id": 1\}}, \textit{Then} the server solves the model to \texttt{OPTIMAL}/\texttt{FEASIBLE}, persists 40 confirmed events to \texttt{schedules}, and returns HTTP 200 with runtime and satisfaction metrics.
    \item \textbf{AC 2.2 \& AC 2.3 (Solver Error Handling):} \textit{Given} a non-existent semester ID (\texttt{999}), \textit{When} \texttt{POST /api/v1/solver/run} is called, \textit{Then} HTTP 404 is returned; \textit{Given} infeasible teaching-load bounds (\texttt{min > max}), \textit{Then} HTTP 422 is returned with diagnostic details.
    \item \textbf{AC 3.1 -- 3.4 (Course Catalog CRUD):} \textit{Given} valid course payloads on \texttt{/api/v1/courses}, \textit{When} creating, filtering by \texttt{?department=CS}, updating via \texttt{PUT}, or deleting via \texttt{DELETE}, \textit{Then} the API returns HTTP 201, 200, or 204 respectively, and rejects duplicate \texttt{course\_code} entries with HTTP 409.
    \item \textbf{AC 4.1 -- 4.3 (Classroom CRUD \& Boundaries):} \textit{Given} room requests on \texttt{/api/v1/rooms}, \textit{When} capacity is negative or zero, \textit{Then} HTTP 422 is returned; \textit{When} filtering by \texttt{?min\_capacity=50\&room\_type=lecture}, \textit{Then} only matching rooms are returned.
    \item \textbf{AC 5.1 -- 5.2 (Preference Upsert \& Slot Validation):} \textit{Given} instructor preference submissions on \texttt{POST /api/v1/preferences}, \textit{When} valid days and catalog slots are provided, \textit{Then} HTTP 201 (or 200 on idempotent upsert) is returned; invalid slot IDs return HTTP 404 and level mismatches (graduate slot for undergraduate course) return HTTP 422.
    \item \textbf{AC 6.1 -- 6.3 (Interactive Preferences UI \& Toast):} \textit{Given} the \texttt{/preferences} page, \textit{When} an instructor toggles days and catalog time slots and clicks \texttt{Save Preferences}, \textit{Then} \texttt{POST /api/v1/preferences} is invoked and a green success toast appears; submitting without a day or slot is blocked with an error toast.
    \item \textbf{AC 8.1 -- 8.2 \& AC 9.1 -- 9.2 (Schedule Matrix, Multi-Filter, Solver Trigger \& CSV Export):} \textit{Given} the \texttt{/schedule} and \texttt{/admin} pages, \textit{When} the user filters by department/keyword, triggers the solver, or clicks \texttt{Export CSV}, \textit{Then} FullCalendar updates without reloading and downloads \texttt{UMKC\_Schedule\_Fall\_2024.csv}.
\end{itemize}
